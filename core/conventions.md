# Conventions

- Prefer clear names over abbreviations.
- Use Markdown for human-readable documentation.
- Keep reusable rules in `core/` and context-specific rules in `contexts/`.
- Avoid duplicating rules across contexts when they can be inherited from `core/`.
- Contexts may be combined rather than treated as mutually exclusive modes.
- Prefer existing repository conventions when they conflict with generic preferences, unless explicitly instructed otherwise.
